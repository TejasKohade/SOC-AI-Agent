# Rule tuning from CASE-284056FE

Case: SSH brute force from a single source on web-01  
Verdict: malicious

- **autosoc-ssh-bruteforce**: Add a secondary correlation: if a successful SSH login from the same source IP follows brute-force failures within a configurable window (e.g., 5 minutes), automatically escalate severity to 'critical' and trigger session revocation as a Tier 2 automated action rather than requiring Tier 3 manual approval, since a confirmed post-brute-force login represents active compromise. Also consider lowering the failure threshold for AbuseIPDB-confirmed malicious IPs from the default to 3 failures before alerting.
